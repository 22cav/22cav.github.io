## The problem

Muon is an optimizer for the weight matrices of neural networks. At each step
it takes the momentum, keeps its singular vectors, and sets all its singular
values to one:

$$
M = U \Sigma V^\top \quad\longrightarrow\quad \text{update} = U V^\top
$$

Every direction in the update gets pushed by the same amount. It
works very well for training transformers.

That flat spectrum is a strong choice. DynMuon, a recent variant, replaces it
with a power of the singular values, $\sigma^p$, where $p$ changes during
training. We asked:
does changing the spectrum improve training, or does it just change the step
size?

## What I did

We put the methods in one family. They all keep the momentum's singular
vectors and differ only in the singular values of the update, that is, in the
function $f$ in

$$
\text{update} = U f(\Sigma)\, V^\top.
$$

The methods:

- **Muon** (flat), **exact-SVD Muon**, and **DynMuon** (scheduled power).
- **DynMuon-Route**, our variant, which lets each layer move its power up or
  down based on a per-layer signal (stable rank, signal-to-noise ratio or
  weight–update alignment).
- **RelMuon**, which takes the update's scales from the weight matrix's own
  spectrum.
- **Controls** that keep the update size fixed but change its shape: random
  values, a chaotic polynomial map (Kaon), and the inverted spectrum, which puts
  the largest step on the weakest direction.

The controls matter because changing the spectrum also changes the size of the
update, which is the same as changing the learning rate. Matching the size lets
us measure the effect of shape alone.

Each run trains a 124M-parameter GPT on 400M FineWeb tokens. We swept the
learning rate for every method and compared them at their best.

## Results

**At a tuned learning rate, nothing beats Muon.** Muon and DynMuon reach the
same loss within seed noise (3.646 vs 3.651). DynMuon's learning-rate curve is
mostly Muon's curve shifted: its schedule acts like a bigger learning rate.
Exact SVD matches Muon's Newton–Schulz approximation but is 1.5× slower per
step, and RelMuon is both worse and almost 4× slower.

**Order matters, exact values don't.** With the update size held fixed,
random singular values barely change the result. Putting the same values in
reverse order, so the weakest direction gets the biggest step, fails.

**Flatter is better, up to Muon.** A fixed-power variant that pushes the
spectrum toward flat improves steadily as it gets flatter, and its best setting
comes closest to Muon. Muon simply takes flattening to its limit.

**Per-layer routing protects against a bad learning rate.** At a tuned rate no
routing signal opens a better optimum; only weight–update alignment stays
within noise of the baseline. But when the learning rate is 2.5–10× too high,
routing recovers 0.017–0.022 of validation loss. It works as a per-layer safety
net for the step size, not as a faster optimizer.

So what matters in Muon's update is its size and keeping larger steps on
stronger directions, not a special spectrum. Plain Muon stays the strongest
cheap default in this family.
